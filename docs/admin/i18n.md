# Translations

Tessera ships in English with a complete French (`fr_FR`) translation. Each user picks a language in
their preferences (`core.user.lang`); the server then answers in that language: menus, actions, field
labels and help, selection values, view labels, workflow buttons, error messages, notifications and
printed reports. The web client is translated separately and follows the same setting.

## Languages

Languages are records of **Settings → Localization → Languages** (`core.language`). Activate a
language to offer it to users. A language is served by the catalogue of the same code, else by a
catalogue of the same base language (`fr_BE` and `fr_CA` use `fr_FR`); anything without a translation
is shown in English. An API client can ask for another language per request with the
`X-Tessera-Lang: fr_FR` header; anonymous requests (the login page) follow `Accept-Language`.

## Where translations come from

Each module carries its translations in `backend/modules/<module>/i18n/<lang>.po` (gettext files).
There are two kinds of server text:

* **read at run time** — field labels, views, error messages, notifications, reports: a new or edited
  `.po` file takes effect when the server processes restart;
* **stored in the database** — menus, actions, pipeline stages, security groups, workflow states and
  buttons, countries, currencies and other module data: each record keeps one value per language.
  These are written when a module is installed or upgraded, and on demand with `tessera i18n load`.

## Loading or updating translations

After deploying new or corrected `.po` files without a module upgrade, re-apply them to the database:

```bash
tessera i18n load                       # every installed module, every language with a catalogue
tessera i18n load crm sale --lang fr_FR # some modules, one language
tessera i18n load --overwrite           # also replace translations edited by administrators
```

Then restart the server processes so that labels and messages use the new catalogues. The command
uses `TESSERA_DATABASE_URL` (or `--database-url`). It is safe to run repeatedly.

Records created by modules as *noupdate* data (countries, currencies, groups, activity types and
similar data an administrator may customise) keep translations you edited yourself: `load` and
upgrades only add the languages such records do not have yet. `--overwrite` restores the catalogue
text. Ordinary module data (menus, actions, stages, workflow buttons) always follows the catalogues.

A translatable value can also be edited in the application: switch your language, then edit the
record (a menu name, a stage); the value is stored for that language only.

## Checking completeness

```bash
tessera i18n stats             # strings per module and how many fr_FR translates
tessera i18n stats --lang de_DE --missing
```

Phase 1 requires at least 95 % per module for `fr_FR`; the backend test suite enforces it.

## Adding a language

1. `tessera i18n extract --lang <code>` creates an empty `i18n/<code>.po` in every module.
2. Translate the `msgstr` lines (any PO editor; keep `{placeholders}` as they are).
3. Activate the language in Settings → Localization → Languages, run `tessera i18n load`, and restart.
